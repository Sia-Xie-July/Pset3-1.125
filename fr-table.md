| ID | Functional requirement | Acceptance criteria |
| --- | --- | --- |
| FR1 | The website shall present the proposed datacenter in Kajaani, Finland, including its location, initial design, and major uncertainties. | The overview displays the proposed location, 20 MW IT load, assumed PUE of 1.25, calculated 25 MW facility load, and baseline annual electricity of 219 GWh. All unverified design values are labelled as assumptions. |
| FR2 | The website shall compare Finland, Canada, and Singapore using consistent indicators, with regional detail for Kajaani and Québec where available. | Users can compare electricity supply, carbon intensity, cooling conditions, water constraints, and grid-connection considerations. Each indicator includes its geographic scope, reporting period, and source; unavailable values are marked as unknown. |
| FR3 | The website shall persistently store evidence, sources, design assumptions, and design decisions in D1. | Saved records remain available across sessions and deployments. Evidence records link to sources, and design claims identify their type and verification status. |
| FR4 | The website shall retrieve at least one genuine dataset from an external API, initially targeting Fingrid electricity data for Finland. | The backend successfully retrieves and validates an API response, then stores the values, units, reporting period, source, and retrieval timestamp in D1. |
| FR5 | The website shall allow authenticated, registered users to ask the AI adviser questions about the design and country comparison. | A registered user can submit a question and receive an answer based on relevant stored evidence and current design assumptions. |
| FR6 | The backend shall prevent unauthenticated or unregistered users from calling the AI endpoint. | Direct API requests from unauthenticated users are rejected. Authenticated users without a registration record are also denied access until registration is completed. |
| FR7 | The AI adviser shall cite the evidence supporting each substantive factual answer. | Citations correspond to real source records and provide accessible source links. When evidence is missing or conflicting, the answer explicitly states the limitation. |
| FR8 | The website and AI adviser shall distinguish facts, estimates, assumptions, calculations, design decisions, and unknowns. | Claims display their classification. Derived values are calculated by application code, and AI answers preserve the distinction between verified evidence and proposed assumptions. |
| FR9 | The system shall retain the last valid dataset when an external API fails or returns invalid data. | A simulated timeout or invalid response does not overwrite valid records. The website shows the retained data, its timestamp, and a refresh-failure notice. |
| FR10 | The website shall show when each data item was last updated and the period it describes. | Evidence displays the reporting period and retrieval or update timestamp. Design assumptions display their last modification date. |
| FR11 | The website shall compare build-and-own, leased compute, and phased hybrid options using a 10-year cash-flow model. | Users can inspect facility and GPU costs separately, review labelled cost assumptions, and compare the three options under consistent demand and service requirements. |
| FR12 | The website shall provide sensitivity analysis and display a base case plus two required stress cases: a one-year delay in full grid power and GPU utilization at half the forecast. | Each case reports cash required before opening, annual operating cost, cost per productive GPU-hour, and capital at risk. Changing an assumption updates the affected calculations. |
| FR13 | The website shall display a system diagram covering power, cooling, networking, and failure paths. | The diagram and accompanying explanation show normal operation, failure of the largest electrical component, and a 48-hour grid outage, including any workload reduction or interruption. |
